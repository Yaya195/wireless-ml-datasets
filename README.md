# Wireless ML Data Hub

**A curated, task-oriented guide to datasets for machine learning in wireless communications.**

Wireless ML Data Hub helps researchers start from the **wireless research problem** they want to study, rather than from an unstructured list of dataset names. The catalogue connects datasets to tasks such as channel estimation, beam prediction, localization, Radio-SLAM, spectrum sensing, wireless sensing, RAN optimization, and more.

Each Task↔Dataset association is evidence-backed. A dataset is not assigned to a task merely because its variables make that task theoretically possible.

## Why this catalogue

Wireless dataset discovery is often fragmented across papers, project websites, data repositories, challenge pages, and general-purpose portals. Dataset names alone also reveal little about the task actually demonstrated with the data.

Wireless ML Data Hub therefore organizes the literature around three principles:

- **Task first.** Wireless research tasks are the primary discovery axis.
- **Evidence before inference.** Task mappings require authoritative documentation or demonstrated use.
- **Structured metadata.** Dataset identity, modalities, technologies, ground truth, access conditions, provenance, and references are represented explicitly so the catalogue can be searched and reused programmatically.

The result is a curated and growing research guide, not a claim of exhaustive coverage and not an automatically scraped directory.

## What a dataset record captures

The catalogue distinguishes between:

- the **wireless task** a researcher wants to study;
- the **dataset, dataset family, or dataset collection** that may support that task;
- relevant **inputs, targets, evaluation references, environment, mobility, and frequency context**;
- **wireless technology** and other controlled technical metadata;
- dataset **origin**, such as measurement, ray tracing, simulation, synthetic generation, or hybrid acquisition;
- **access, licensing, provenance, and verification status**;
- evidence supporting every Task↔Dataset association.

A dataset may support several wireless tasks, and a task may have many datasets. Task↔Dataset is therefore modeled as a many-to-many relationship rather than forcing each dataset into a single category.

## Curation model

Wireless ML Data Hub separates what a dataset has been **demonstrated to support** from what it may be **technically suitable for**.

Task mappings require evidence from authoritative dataset documentation, the associated publication, an official challenge, a maintainer-provided implementation, or another documented research use. Technical suitability can guide future curation, but does not by itself create a task mapping.

Dataset identity is also treated separately from publication identity. The catalogue checks canonical identifiers, aliases, versions, and relations to reduce accidental duplication.

See the [curation guidelines](docs/curation-guidelines.md) for the full methodology.

## Repository structure

```text
data/
  datasets/          Canonical core dataset metadata
  tasks/             Wireless-task definitions
  collections/       Cross-cutting thematic collections
  resources/         Supporting benchmarks and discovery resources
  vocabularies.yaml  Controlled vocabularies

catalog/
  README.md           Generated task-oriented catalogue
  datasets.md         Generated all-datasets index
  resources.md        Generated supporting-resource index
  technologies.md     Generated wireless-technology index
  tasks/              Generated task pages
  datasets/           Generated dataset profiles
  collections/        Generated cross-cutting collection pages
  technologies/       Generated technology pages

dist/
  catalog.json        Generated machine-readable catalogue

schema/               JSON Schemas
scripts/              Validation, auditing, duplicate checking, and generation
tests/                Repository integrity tests
```

The files under `data/` are the source of truth. Files under `catalog/` and `dist/catalog.json` are generated and should not be edited manually.

## Machine-readable use

`dist/catalog.json` contains populated tasks, core dataset records, cross-cutting collections, supporting resources, task categories, and controlled vocabularies. It is intended for downstream interfaces such as search tools, websites, analyses, and grounded assistants without requiring Markdown parsing.

See [Machine-readable catalogue](docs/machine-readable.md) for the format and update policy.

## Contributing

Contributions are welcome when they improve the scientific usefulness or accuracy of the catalogue. You can suggest a dataset, report incorrect or outdated metadata, propose a missing wireless task, suggest a supporting resource, or submit a structured record.

Before contributing, read [CONTRIBUTING.md](CONTRIBUTING.md) and the [curation guidelines](docs/curation-guidelines.md). The project deliberately favors evidence and metadata quality over raw catalogue size.

## Citation

If you use Wireless ML Data Hub in research, please cite the catalogue using [`CITATION.cff`](CITATION.cff) and also cite the **original dataset publications or providers** relevant to your work. Inclusion in this catalogue is not a substitute for citing the underlying dataset creators.

## Scope

The catalogue focuses on reusable datasets and dataset collections relevant to machine learning for wireless communications and closely related wireless sensing and network-intelligence tasks.

A channel model, simulator, paper, code repository, or benchmark claim is not treated as a core dataset unless a reusable data resource is actually available and appropriately identified. Benchmark frameworks, evaluation suites, and discovery portals that are useful but are not core datasets are represented separately as supporting resources.
